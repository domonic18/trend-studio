## 3. 跨仓文档与真相源优先级

本仓是**云端契约的真相源**；同族另两个插件仓是消费方口径：

| 仓库 | 文档 | 关系 |
|---|---|---|
| `dsh-plugin-trend-coach` | `docs/requirements/` `docs/architecture/` | 学员端消费方；接口字段以本仓清单为准，插件侧渲染与离线策略以插件文档为准 |
| `dsh-plugin-trend-producer` | `docs/requirements/` `docs/architecture/`、`skills/README.md`、`docs/research/` | 生产端消费方（M9/M10）；**生产编排、Skill 工艺与调研结论以插件仓为准，接口契约以本仓为准**；插件仓内 `docs/research/` 为调研材料（非契约），采纳结论会回写本仓架构 ADR |

冲突裁决：接口字段与错误码 → 先改本仓需求/架构/清单，再同步插件仓；插件侧实现方式与渲染 → 改插件仓，契约没变就不动本仓。

## 4. 维护规则

- 新增文档：放入对应 `docs/<类别>/`，并在第 1、2 节登记。
- 接口变更：需求 → 架构 → 对接清单 → OpenAPI → 实现 → 测试，一次改齐。
- 里程碑或待冻结事项定稿后，更新对应文档的状态与结论，不留过期条目。
- 文档只写结论与依据，不复述代码实现细节；代码变化不必逐条回写文档，契约与不变量变化必须回写。
