## 2. API 约定

- 协议：HTTPS + JSON；请求与响应均为 JSON 对象（数组只能作为对象字段）。
- 版本：路径前缀 `/v1`；破坏性变更升 `/v2`，不在一期内做兼容分支。
- 时间：`expiresAt` 为毫秒时间戳；`startSec/endSec` 为整数秒。
- ID：
  - `segmentId`：`^seg-[A-Za-z0-9._-]+$`，≤80，全局唯一、跨版本稳定；
  - `courseId`：≤64，`[A-Za-z0-9._-]`；
  - `chapterId/knowledgePointId`：非空、稳定，与转写/文章/片段共用。
- 错误：HTTP 状态码承载语义，响应体 `{ "error": "string" }`（待冻结为统一错误对象）；禁止 HTML 错误页。
  - `400` 入参非法 / 结构不合法；`401` 未授权或过期；`403` 设备不匹配或越权；
  - `404` 片段不存在或已下架；`413` 请求过大；`422` 未识别到语音；`429` 限流；`5xx` 服务故障。
- 分页：检索等定长接口不分页；后台列表与管线接口使用 `offset/limit`（`offset` 0–100000、`limit` 1–100），响应回显 `total/offset/limit`。
- 幂等：事件接收按 `event_id` 幂等；其余只读接口天然幂等。设备码与刷新不是幂等接口，客户端按契约重试。

## 3. 边界与体积

| 项 | 上限 |
|---|---|
| `query` | 去首尾空白 1–500 字符 |
| `topK` | 整数 1–20，默认 5 |
| 单片段 `text` | ≤4000 字符（云端建议裁剪到 ≤2KB，待冻结） |
| 标题 / 展示标题 | 1–200 字符 |
| 单次检索响应 | ≤512KiB |
| `relatedKnowledgePoints` | ≤5 条，仅 `knowledgePointId/title` |
| 请求体 | 默认 ≤128KiB（检索/播放/事件），超限 `400`/`413`；ASR 路由 ≤3MiB |
| 语音音频 | 解码后 ≤1,920,044B；PCM/单声道/16000Hz/16bit；时长 1–60,000ms |
| 转写文本 | 清洗后 1–2000 字符；空结果 `422` |
| 视频上传 | `application/octet-stream`，≤2GiB；可选 SHA-256；鉴权/限流先于 body |
| 视频时长 | ≤14,400s；必须有视频与音频流 |
| 长音频切块 | ≤480s；转写分组 ≤30s；生成窗口 600s、≤24 窗口 |
| 片段草稿 | ≤120s、1–4000 字符；超限在转写片段边界拆分 |

- 越界返回 `400`，不截断后继续；响应超限整体失败，不静默裁剪。
- 校验失败的错误信息可读，但不回显完整 query 或内部字段名之外的内容。

## 4. 安全

- **令牌**：只存哈希；access/refresh 轮换时旧 refresh 立即失效；设备不匹配 `403`。
- **凭据管理**：数据库口令、签名密钥、CDN 密钥走环境变量/密钥管理；ASR/LLM/embedding 连接与密钥存数据库（仅 admin 维护，AES-256-GCM 加密，只回显掩码）；不提交 `.env`、证书、密钥文件。
- **日志**：不记录 token、完整 query、完整 `deviceId`、完整播放地址、用户标识；排障使用 `request_id` 与哈希/截断前缀。
- **限流**：按用户 + 设备 + IP 维度；超限 `429`，响应不泄露配额细节；后台与内容管线独立配额。
- **越权**：学员令牌不得访问后台接口；所有资源访问按 `user_id`/`device_id` 过滤。
- **媒体**：签名 URL 短时效、绑定设备与会话、并发受限；不提供源站直链或整片下载。
- **内容**：云端文本视为不可信数据（对插件而言）；不下发任何可执行指令或脚本。
- **ASR**：学员语音音频只在请求生命周期内转发上游，不落盘、不写对象存储、不写数据库；上游错误只记类别，不透传 `status_msg`；不自动重试。
- **视频管线**：上传先鉴权与限流再消费 body；流式写临时文件，校验通过后原子 rename；ffmpeg/ffprobe 只经 `spawn` 参数数组调用，禁止拼接 shell；源路径、SHA、ffmpeg stderr、provider 原始响应不进响应与日志；HLS 原子发布前校验 `#EXT-X-ENDLIST` 与分片完整。
- **内容 LLM**：只允许管理端调用；密钥只存数据库密文；提示词版本入库；输出必须经 schema 校验与安全 Markdown 校验；生成结果只写 `draft`，禁止自动发布；预算超限整体失败，不部分落库。
- **模型配置 API**：`/v1/admin/model-configs/*` 仅 `admin`；密钥写入后不可读，响应只含 `apiKeyMasked` 与 `apiKeyConfigured`；`PATCH apiKey=""` 表示保留原值；新增/修改不得把密文或明文写入日志；每个用途最多一个启用默认项。
- **依赖**：只引入必要运行时依赖；新增依赖前评估维护状态与许可证。

## 5. 隐私与合规

- 数据最小化：只采集提供服务必需的字段。
- 支持注销：注销后用户令牌全部失效，按策略清理/匿名化数据。
- 指标事件必须鉴权、字段白名单、用户同意后上报且可撤回；未登录或无同意不上报。
- 事件字段白名单（M2）：`search_requested`（耗时、topK、命中数、是否空召回）、`citation_clicked`（segmentId）、`player_started`（起播耗时、是否自动播放被拒）、`feedback_submitted`（评分 up/down）。**不含** query 原文、回答内容、完整播放地址、反馈分类与备注。
- 敏感字段脱敏后再入库或入日志。
- 学员语音音频与转写文本不持久化、不进入指标；日志只记错误类别与耗时，不记 base64、正文或完整 deviceId；ASR 密钥存数据库密文，仅后台可维护。
- 建课源视频、长音频转写与生成草稿用于内容生产，按管线规则持久化；默认不自动清理，留存期限由运营按版权授权确认。转写正文只经管理端转写接口返回，日志与指标不记正文。

## 6. 数据与索引

- 迁移脚本可重复执行、可回滚；生产变更前在 staging 演练。
- 发布与索引分离：未审核内容不得进入检索；下架通过状态位而非物理删除。
- `segmentId` 一经发布不可复用；片段内容变更保留 ID。
- 索引重建采用新版本双写 + 切换，不使用长时间锁表。
- 存量与增量索引任务记录状态与耗时，失败可重跑且幂等。
- 管线任务与内容状态分离：`pipeline_jobs` 记录执行，`media_assets/transcripts/content_generations` 记录结果；重试不得产生重复 active job，apply 必须幂等。
- 生成内容只写 `draft`；`publish` 是唯一进入学员可见性的入口，配置 embedding 时必须先成功 `reindex`。
- 素材不物理删除；归档用 `status=archived`，并确保播放与发布忽略归档素材。

## 7. 测试

- 每个接口必须有契约测试，覆盖对接清单 §6 全部用例。
- 纯逻辑（入参校验、RRF、阈值回退、签名构造）必须有单元测试。
- 检索质量变更必须跑评估集（≥100 条，Top-5 ≥90%）。
- 媒体链路测试覆盖：加密 HLS 解密、seek、Range 206、CORS、过期 token。
- 语音测试覆盖：WAV 校验边界、上游成功/业务错误/429/5xx/超时/非 JSON、空文本、鉴权与限流、日志脱敏；真实上游作为待验项。
- 管线测试覆盖：纯算法（切块、时间戳合并、锚定、ID）、假 provider 的 ingest→生成→apply→发布 E2E、取消/重试/心跳恢复、上传边界与错误码、响应脱敏、OpenAPI 双向一致；真实 ffmpeg 用例由 `RUN_FFMPEG_TESTS=1` 门控。
- 安全测试覆盖：缺失/过期令牌、设备不匹配、越权、限流、日志脱敏抽查。
- CI 必跑：类型检查、单元测试、契约测试、OpenAPI/实现一致性校验。

## 8. 可观测性

- 所有请求带 `request_id`，响应回传；日志结构化。
- 检索、授权、播放、事件、语音、管线分别记录关键指标（见架构 §10）。
- 错误按状态码分桶，不把“空召回”与“服务故障”混在一个指标。
- 管线指标按 `kind/status/stage` 聚合，不把素材 ID、课程 ID 或转写正文作为标签。
- 告警覆盖 5xx/429、检索 P95、索引任务失败、管线任务连续失败/队列积压、证书到期、签名失败率。

## 9. 代码与提交

- 语言与框架在服务骨架落地时确定；类型检查与格式化进 CI。
- 模块边界按接口前缀（`auth`/`kb`/`playback`/`events`/`content`/`asr`/`pipeline`），跨模块只经公开函数；`pipeline` 复用 `content` 的校验与 `reindex`，不复制内容 CRUD。
- 注释只写“为什么”（非显而易见的约束、兼容、安全原因），不写“做什么”。
- 提交遵循 Conventional Commits：`feat|fix|refactor|docs|test|chore`，分批提交，提交前检查敏感信息。
- 不提交构建产物、依赖目录、密钥、`.env`、日志、测试视频大文件。

- 新增接口或字段：需求 → 架构 → 对接清单 → OpenAPI → 实现 → 测试，一次改齐。
- 目录与命名见 [项目结构](../ai-context/project-structure.md)；文档索引见 [文档总览](../ai-context/docs-overview.md)。
