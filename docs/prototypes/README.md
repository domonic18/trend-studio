# 端到端界面原型（2026-11-09）

本目录是**全系统三端界面原型**的单一真相源，用静态 HTML 表达「屏幕长什么样、交互怎么走、每个元素挂在哪个 dsh 扩展点上」。目的：需求→界面→实现三方对齐，避免「边做边改」。

- `coach-learner.html` —— 学员端（dsh + `trend-coach` 插件）
- `producer-workbench.html` —— 教员端（dsh + `trend-producer` 插件）
- `admin-console.html` —— 管理台（云端 `/admin` 网页，不在 dsh 里）
- `apps/producer/prototype/section-preview.html` —— （保留）节内呈现层的**视觉**参考；能力清单以 `packages/widgets/src/dsl.ts` 块白名单为准

每页顶部有屏幕切换器；每屏底部有状态条，标注四档：

| 标记 | 含义 |
|---|---|
| ✅ 已实现 | 当前代码就是这个形态（版本见括号） |
| 🔶 增强 | 已有基础，本原型画出目标交互，待排期 |
| ⛔ 缺口 | 需求文档有、实现没有 |
| ◻ 候选 | 未排期，进原型只为完整表达愿景；动工前须先验证可行性 |

## 可实现性约束（画原型的铁律）

本系统以 **DeepSeek Harness（dsh 0.2.1-rc.5）** 为客户端基座，dsh 里的界面原型必须落在 dsh 真实存在的扩展点上——凡是 dsh 做不到的，一律不画：

1. **布局 = 左会话 + 右侧栏**。dsh web 应用面只有这两栏；右侧栏以 tab 组织（`ctx.sidebarRightTabs.register` + `sidebar.right.pane.tab` 槽两段式注册）。不画独立窗口、不画脱离 dsh 的全屏应用、不画系统级浮层。
2. **会话侧的交互只有四种**：普通消息（markdown/结构化文本）、引用链接（coach 用伪域名 `trend-coach.local` 拦截点击路由到右栏面板）、按钮问题卡（dsh 原生 QuestionCard，教员端两道门禁用它）、composer 增强（附件/语音按钮、选中文本检测——均已实现）。
3. **视频只在右栏播放器 tab 内嵌 HLS**（签名播放会话）。不画「视频浮在课程页上」——画中画联动（video-sync）列为候选，须先验证 dsh 右栏内嵌播放器的可行形态。
4. **机密只在宿主侧**：浏览器半不碰 token/密钥，登录动作发给宿主走授权流；设置页粘 key 是 dsh 原生能力（provider `apiKeyEnv` ref）。
5. **命令面（`/trend login` 等）只是备用**，原型一律以面板/按钮为主路径。
6. **管理台与门户是云端自己的 SPA**，不受 dsh 约束，按普通网页设计。

## 与需求文档的关系

- 需求真相源：`apps/{cloud,coach,producer}/docs/requirements/product-requirements.md`
- 本原型**不改需求**，只把需求翻译成界面；发现需求与界面矛盾时，回头改需求文档并在本 README 记一行变更。
- 呈现层块能力（哪些 DSL 块/课件类型存在）以 `packages/widgets/src/dsl.ts` 为准，原型不新增块；要加块先走 widgets + DSL 文档，再回填原型。
